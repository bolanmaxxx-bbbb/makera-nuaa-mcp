# 参数采集与阶段要求

先按workflow-design.md选择引导、模板或自定义方式，再按实际依赖询问。下面是可选信息模块，不是每个任务必走的固定顺序。用户已提供的内容从对话复用。“确认”指确认缺失的选择和实际条件，不要求每个读操作或原生按钮另行批准。

| 阶段 | 优先补齐 | 本阶段可做的工作 |
|---|---|---|
| 任务与几何 | 软件测试/正式方案/仅讨论；模型、单位、目标尺寸、加工方向、孔为通孔还是盲孔；只雕刻表面还是制取独立零件 | 只读模型及尺寸核对 |
| 毛坯与基准 | 材料、名义尺寸、实测方式与当前装夹；底部承托面、垫层、加工区域；厚度方向是否就是成品长度 | 拟定测量与基准方案，不执行探测 |
| 长度形成 | 定厚/已等厚/背面加工；所需去除量；面铣后复测与Z参考；公差 | 形成完整工艺草案 |
| 刀具与工艺 | 刃径、柄径、有效刃长、刀材、铣刀刃数与端刃形状；钻尖角；伸出与肩部间隙；参数依据 | 比较方案，计算参数派生量 |
| 约束与保留 | 压紧位置、刀具通道、薄壁支撑、连接筋/底座、分离与修整 | 检查工序依赖与可达性 |
| CAM操作 | 当前MCP能力、工艺认可、几何区域、工具映射、具体切深/转速/进给/下刀/层深 | 授权范围内的原生软件操作 |
| 交付 | 全部必需工序覆盖、回读一致、仿真、用户要求的NC和复核项目 | 交付当前真实完成阶段 |

## 参数来源与尺寸区分

- `stock.nominal_mm.z` 是采购/草稿值；只有选择需要实测厚度的流程时才采集`stock.measurement`。已有合格原料、表面雕刻、翻面加工等按各自需求选择依据，不强制采用顶底测量法。
- `target.z_mm` 是板厚方向成品尺寸；操作的 `depth_mm` 是相对于该工序参考面的切深。
- `scope=cam_test` 必须来自用户明确要求的软件测试，`test_limits_mm` 限定工序深度；不能由能力缺口自动降级。
- `setup_id` 标识当前装夹。所用测量必须对应其装夹、基准与当前确认；移动垫板、重新装夹、改零点后重新核对受影响数据。
- 测厚公式（Z向上）：`实际厚度 = top_z_mm - bottom_z_mm - interlayer_mm`。这里bottom是材料承托平面；未知间隙不能默认为0。有可靠直接测量方法时，可使用direct测量值并记录方法和依据。
- 面铣方案：目标厚度由 `thickness_control.target_mm` 表达，面铣操作声明 `target_thickness_mm`；CAM具体去除深度应等于实测厚度减去目标厚度，并说明后续参考面。
- 表面雕刻使用明确雕刻深度、顶面基准和不会穿透的厚度依据，无需强行定厚到4 mm。
- 对复杂3D形状、多次装夹或翻面，扩展明确的尺寸链和工序覆盖说明，不把板材单面规则直接外推。

## 加工参数

使用适用于实际刀具、材料和工况的厂家资料；对未知牌号保留未知，并解释暂定参数的依据和限制。不得把“铜”库标签直接视为磷青铜已验证预设。

铣削检查 `F = n × 刃数 × 每齿进给`，钻孔检查 `F轴向 = n × 每转进给`。同时考虑机床限制、全槽/侧铣、刀具伸出、刃长、负载、排屑和冷却。行距设置不证明实际侧向吃刀宽度。

通孔还需确定钻尖几何、完整孔径贯穿所需行程和垫板可切入余量；刀长不能直接等于许可深度。铣刀6.5 mm或钻头10 mm刃长不意味着可直接使用同样的加工深度。

## 提问示例

用户：想用Makera加工这个模型。

第一轮只补任务范围和形状：“要得到独立零件，还是只在表面雕刻？最终尺寸和允许误差是多少？模型中哪个方向沿材料厚度？”不把整张后续设备调查表一次抛给用户。

已知4 mm成品、5.5 mm名义毛坯时，下一轮聚焦：“厚度在当前装夹位置实测过吗？打算先定厚到4 mm，还是采用背面加工/其他方式？”没有实测可先讨论计划，但不能直接把1.5 mm当成最终去除量。

## 文件记录与校验结果

任务JSON是记录，不是新的授权来源。`plan_confirmed` 应对应用户实际认可完整工艺的回答；不能由模型自行把未获回答的问题填为true。

`check_job.py`是无副作用的记录校验器。通用路线检查目标覆盖、依赖和交接；选用板件专用模板时再增加厚度计算和定厚检查。它不验证探测数据真实性、工件碰撞、材料适用性或现场安全。检查失败时可继续独立只读工作和提问，不能绕过失败项执行其依赖步骤。

对正式CAM，当前适配器缺少面铣定厚验证时，即便已有钻孔和轮廓能力，仍不能完成需要定厚的整件任务。应列出已完成/未完成工序，不声称完整成品。

## 记录字段与脚本阶段

通用模板job_kind=custom；requirements和workflow的字段见workflow-design.md。plate_part是可选的单面板件专用规则，surface_engraving是只含明确雕刻深度的简化规则，不是必须经过的中间阶段。

工序字段：id、kind、tool_id、geometry_region（实际几何UUID及区域说明）、reference、depth_mm、rpm、feed_mm_min、plunge_mm_min、stepdown_mm、parameter_basis。depends_on声明前置工序；changes_setup和reestablish_datum声明装夹切换。参考面应可核对；板件专用规则的轮廓和通孔reference=finished_top，其余路线需明确自己的尺寸链。

刀具字段：id、kind（endmill/drill/engraver）、diameter_mm、shank_mm、flute_length_mm、material、geometry、reach_evidence；铣刀还需flutes。reach_evidence记录实际伸出、刀肩和夹持间隙的核对依据，不是把刃长当作全部可用行程。所有示例数值由任务确定，不从案例复制。

钻孔需hole_type=blind/through。单面板件通孔规则使用tip_angle_deg、breakthrough_mm、spoil_allowance_mm计算从定厚顶面起的完整贯穿行程；通用路线用through_depth_basis明确其材料厚度、钻尖、参考面与垫板余量依据，随后核对实际数值。该自由文字字段本身不证明深度合理。

板件专用规则还需retention.method、remaining_stock_mm（轮廓未切透的底皮高度；仅留局部连接筋时可为0）和separation_plan；连接筋实际几何仍需从CAM回读核对。它不要求一定使用连接筋，允许合适的其他保留/夹持方案。定厚顺序不同于模板时说明workflow.order_override_reason，并先核对依赖；复杂路线使用通用模式。

- plan：检查流程结构与目标覆盖，可暂缺实测/切削参数，结果不代表可执行。
- cam：检查已认可计划、实际输入/刀具参数和当前MCP能力，表示可继续相应软件计算，不代表现场可加工；人工步骤保留交接警告。
- delivery：再检查当前修订的实际计算、保存回读、必要仿真/NC及外部步骤验收证据。
- machine：当前始终不放行，不通过本脚本获得现场运动授权。

CLI退出码0表示请求阶段的记录检查通过，2表示缺项/阻塞，3表示输入文件或结构错误。输出next_question_group和最多3个next_items用于下一轮提问；若缺口属于软件能力而非用户参数，直接解释能力缺口，不向用户索取无法提供的参数。
