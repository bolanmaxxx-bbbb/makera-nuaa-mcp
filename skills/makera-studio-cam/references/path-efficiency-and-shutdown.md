# 走刀效率与程序收尾

用于长直槽、分层往复、重复覆盖、低效返程或加工后主轴继续转的复盘与验收。先区分用户的现场反馈、当前保存工程、实际上机NC和控制器状态；它们可能不是同一修订。缺少最终NC时保留具体原因未确认，不把推测写成修复结论。

## 每个长行程都要有用途

比较去程和返程的实际XY/Z、层深、进给模式、刀具参与范围，以及换层、进退刀、空走距离。对长槽提出可行候选：单向切削加快速安全返回、允许顺/逆铣交替的往复逐层切削，或合适的区域清理。比较预计有效切削时间与空走时间；没有完整NC或仿真时明确时间只是估算。

- 往复不等于每个方向都在去除新材料。在同一Z层沿几乎重合的两条长边来回走，返程可能主要清理已有槽壁。窄闭合轮廓可以生成非空轨迹，但不能因此成为默认的高效直槽方案。
- 用户所说“返程不进给”可能是返程空走、没有新一层Z进刀、没有新材料参与，或仅仅没有重复写F。标准G-code中的F通常有模态继承；先核对G0/G1与Z，不能只数F出现次数。
- 双向每程加深可能提高利用率，但也改变顺铣/逆铣方向、端部进入、切削力、排屑和留筋受力。不能为追求效率一律强制双向，也不能让刀具在夹具、未清除材料或留筋上快速返回。
- 单向策略有质量或夹持依据时可以保留，记录理由。当前MCP没有接通专用的“往复每程加深”生成器，不能把改变轮廓位置或画窄矩形当作已实现该策略。

`audit_saved_toolpath(path, operation_index)`只读MKS的有序GL_LINES顶点对，检查相邻反向长行程、同层关系和几何覆盖。返回工程SHA256、当前计算证据标志及样例。覆盖比例是长条几何近似，不能证明实际空切、余料去除或加工时间；显示网格不含完整G0/G1、F、抬刀和控制器执行信息。`saved_calculation_evidence_verified=false`时先处理失效刀路，不能将旧显示轨迹当作当前参数的计算结果。

## 收尾是独立的交付项

CAM计算完成不等于NC已导出，NC结束也不等于现场主轴已经停稳。对最终实际交付的每份NC分别核对：

1. 最后切削之后的安全退刀、结束位置和夹具净空有依据；不随意套用其他机型的G28/G53/换刀命令。
2. 最后有效启主轴之后、最后进给运动之后有明确的停主轴指令。标准M5是检查线索；仍须确认目标Z1及所选后处理的兼容性，不将Carvera或LinuxCNC文档当作Z1固件证明。
3. 使用过的冷却/气路有相应关闭指令，并有目标设备的定义；检查末尾是否又打开主轴或冷却。
4. 有目标控制器支持的程序结束标记。不能只因有M2/M30就假定其隐含停机行为已在当前设备验证。
5. 程序没有停在等待确认的中间节点；实际结束后观察主轴减速并停稳。当前服务不能读取可信的主轴转速、执行M5或验证物理停机，需要用户/受支持设备层提供现场证据。

`inspect_nc_file`保留原有字面字段，新增`sequence_audit`。它按顺序检查受限标准指令：头部/注释中的M5不能代替末尾停机；结束标记之后的M5不可作为可达证据；启动后又停止/停止后重启要按顺序判断。选跳、宏、子程序、未知控制或同组冲突不会得到完整通过结果。`restricted_sequence_check_passed`只代表这项受限文本检查，不是仿真、后处理验证或机器已停。

检查只读，不自动追加M5/M9/M30，不改写上机文件。若要修正具体NC，先取得最终文件和后处理依据，保留原件，在独立副本中修正并重新校验/仿真；代码出现在末尾不证明控制器执行过它。

## 交付证据与修订

正式CAM交付时，每个非钻孔旋转刀具工序的证据中记录：

```json
{
  "efficiency_review": {
    "reviewed": true,
    "direction_strategy": "one_way",
    "basis": "实际轨迹/NC检查记录及所选单向策略的理由"
  }
}
```

`direction_strategy`可为`one_way`、`reciprocal`、`closed_loop`或`other`。字段表达检查结论，不自动证明加工性能。`check_job.py --stage delivery`检查此记录；交付NC时还要求`evidence.nc_inspection`包含最终实际文件的path、SHA256和受限收尾检查结果，哈希须与当前文件一致。已有的后处理和仿真要求继续保留，不能用文本检查替代。

几何、刀具、层深、方向、连接筋或坐标变化后，重新生成受影响轨迹，并作废效率、仿真和NC收尾的旧证据。多装夹中区分主刀路中心、辅助补切范围和整个工程包围中心；平移主刀路后重新核对板边是否仍切通，旋转后的接刀位置是否相符。

## 本轮复盘归纳

这次开发中暴露的问题包括：未配置完成的默认刀/偏置仍显示在工程中；开放直线原生状态显示完成但没有运动数据；以窄闭合轮廓替代直槽后缺少效率比较；修改后的参数和旧轨迹同时存在；留筋未按全部刀具扫掠验收；位置变化没有先完成端点/接刀复核；以及现场反馈的结束后空转缺少最终NC与停机证据。后续分别按配置、真实运动、效率、留料、定位、程序收尾验收，不以“按钮成功”或“有一条线”宣称完整加工就绪。

本文只公开通用经验，不包含现场工程、坐标、照片、实物清单或私有对话资料。

标准语义参考：[LinuxCNC G-code概览](https://www.linuxcnc.org/docs/html/gcode/overview.html)、[LinuxCNC M-code文档](https://github.com/LinuxCNC/linuxcnc/blob/master/docs/src/gcode/m-code.adoc)。这些用于说明受限检查器的语义边界，不证明Makera Z1兼容。
