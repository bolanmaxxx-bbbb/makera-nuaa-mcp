# Makera 加工任务向导

使用 `makera-studio` MCP 执行已验证的软件动作；本技能负责参数采集、工艺计划和阶段验收。保持中文沟通，沿用用户已经确认的信息。先满足完整任务的工艺要求，视频只作为辅助证据。

## 工具入口与能力核对

先调用当前连接的get_capabilities并核对实际暴露工具。使用[工具路由表](assets/mcp-tool-map.json)和`scripts/mcp_workflow.py audit`检查覆盖；它为已验证版本的36个工具提供入口，不要求每个任务调用所有工具。工具出现但能力声明缺失、旧进程或新增未知工具时，先澄清该连接能力，不从磁盘版本推断可执行。

- 项目、毛坯、几何、刀具、区域清理/轮廓/钻孔、起止深度、计算保存、原生状态/方法诊断：读[MCP执行与验收](references/mcp-execution.md)。
- 导入STL/SVG、选择方形/圆棒毛坯或材料/规格时，使用同一参考中的v0.6流程。用户询问其他功能或扩展工作流时读[能力覆盖清单](references/capability-coverage.md)，不要把规划选项当作已接通能力。
- 涉及三维模型的方向/高度、模型与二维工序对应关系，或连接筋实际留料时，读[几何摆放与留件验收](references/geometry-and-retention.md)。区分局部尺寸与保存变换后的尺寸；不以输入框、刀具名称或筋宽设定值代替实际几何证据。
- 创建/继续/修订持久任务、job字段映射和实际调用参数：读[任务与调用参数](references/task-and-payloads.md)。新任务使用create_cam_task，继续时get/list，参数改变用完整spec调用revise；不凭摄像头或计划自动推进阶段。
- 用户需要观察或记录现场时：读[视频与NC辅助流程](references/observation-and-nc.md)，接通状态、订阅、单帧/连续采样、状态组合、上下文、事件和本地ZIP导出；无需视频时不要求地址或开启相机。
- 用户提供NC文件：同一参考中的inspect_nc_file用于文本检查，不等于生成NC、仿真或发送加工。

## 1. 判断当前请求

- 区分：`discussion`（仅讨论）、`cam_test`（明确授权的软件测试）、`production_cam`（正式加工方案/刀路）。不要因某功能未实现，把正式任务自行降为浅层测试。
- 区分旋转刀具加工与激光；当前适配器只验证了部分旋转刀具 CAM，不把其他品牌“Z1”或 Carvera 的指令套到 Makera Z1 Pro。
- 判断是表面雕刻、孔、型腔、独立零件、三维表面、多面加工或组合任务，记录用户关注的尺寸和质量要求。只有涉及成品厚度时才选择相应厚度形成方法。
- 用户只讨论时，不修改项目、刀库、配置或机床。编写技能本身不授予未来加工权限。

## 2. 让用户选择制定流程的方式

先读 [自由工艺流程](references/workflow-design.md)。提供三个入口：引导推荐、选择模板、自定义工序。用户已有明确流程时直接进入自定义，不再强行走模板问卷。

按 [工艺选项](assets/workflow-menu.json) 展示与目标有关的少量方案。模板只是起点，允许增删、重排、拆分工序、增加手工交接和翻面；解释受影响的定位、支撑和验收要求。只有用户明确选择板厚控制方案时，才使用相应测厚/定厚模块；不要将历史任务的流程变成默认流程。

以“目标及验收条件 → 满足该目标的输入或工序 → 依赖关系 → 执行与证据”建立计划。区分必须满足的设计要求与可选择的加工方法；某个设计要求无需加工时，记录已满足的依据。不能悄悄删除目标来适应当前MCP能力。

## 3. 分阶段补齐信息

按 [参数采集与阶段要求](references/intake-and-stages.md) 采集。以 [任务模板](assets/job-template.json) 建立每个任务自己的记录，技术字段和文件哈希由工具读取，不要求用户手填。

每次只问当前阶段最关键的缺项，一般 1–3 个简短问题；优先使用可选答案。需要答案的步骤保持等待，可继续独立的只读检查。用户已确认的信息不重复询问。型号、材料或测量条件变化时，仅重新确认受影响的项目。

每条重要数值记录来源：用户确认、文件读取、当前测量、名义值或暂定值。“不知道”保留为未知，并说明它阻塞哪个阶段；不得默填成已测量/已验证。

## 4. 按任务选择检查模块

通用检查包括几何/单位与目标、材料、刀具与可达性、定位与夹持、工序依赖、参数依据、排屑/冷却、结果验收。按目标再选孔加工、型腔、薄壁、曲面、翻面、板厚控制或保留分离等模块。详见自由工艺流程中的模块表；不把所有模块逐项询问一遍。

以下为可选的板厚控制模块，适用于最终板厚方向尺寸属于任务要求时；默认通用模板不强制它。专用记录可用 [板件模板](assets/plate-part-template.json)，此模板应用更严格的单面板件规则；其他路线使用通用模板声明自己的目标及依赖。

使用板厚模块时，区分成品目标、名义毛坯、当前测量和各工序切深；可选等厚原料、面铣、背面处理或外部加工。测量方式按装夹条件和精度需要选择，底顶面差值只是其中一种。薄壁支撑、基准传递及分离方式按所选路线核对，不强制统一工序顺序。

## 5. 先验证计划，再操作

保存任务 JSON 后运行：

```text
python <本技能目录>/scripts/check_job.py <job.json> --stage plan
python <本技能目录>/scripts/check_job.py <job.json> --stage cam --capabilities <当前get_capabilities结果.json>
```

解释 `missing`、`blocking` 和 `next_question_group`，先补最早的依赖。程序只检查记录的一致性，不会自行确认实测真实性或证明加工安全。

在执行工序前向用户展示简洁的完整计划：目标和验收 → 已有条件 → 所选工序及依赖 → 定位、刀具与参数依据 → 交接与最终检查。只列任务涉及的模块。需要用户选择的工艺或尚未授权的范围，得到回答后再执行；已有明确授权下的常规软件步骤无需逐按钮重复请示。

## 6. 按当前 MCP 能力逐步执行

操作前读 [MCP执行与验收](references/mcp-execution.md)，调用实际挂载服务的 `get_capabilities` 并核对版本/工具存在。代码目录更新不代表当前进程已更新。

根据task-and-payloads.md使用mcp_workflow.py生成阶段参数；helper不执行调用。创建后使用真实返回index并刷新文件快照；配置后先比较选刀返回参数与计划，再执行生成和保存回读。逐条检查返回值，不能把阶段JSON当作无需检查的批处理。技能job.revision与服务task.revision分别保存映射。

- 使用隔离项目副本，记录原模型哈希。当前适配器仅接受服务项目 `cases/` 下的 `.mks`。
- 针对每一工序：核对目标几何 → 配置 → 选刀 → 原生生成 → 保存 → 文件回读。选刀只更新编辑器，新参数在生成时提交。
- 检查实际保存的刀径、刃长、柄径、转速、进给、层深、工序切深、工序顺序和刀路数据；不能只看界面文字、排队成功或单个状态标志。
- 处理钻孔时区分孔形显示网格与实际运动路径。需要啄钻时，核对有序刀路中的下钻及退屑动作，不能仅凭刀库层深推断。
- 需要的面铣、仿真、后处理或设备能力尚未支持时，明确报告具体缺口，保留已完成结果；不得跳过、借另一工序冒充，或用未经验证的任意Qt槽/鼠标键盘来补齐。
- 超时属于结果待核对。先读取实际状态再决定是否重试，避免重复工序/刀具。未知模态提示、项目切换、适配版本不符时停止相关写入。

## 7. 阶段完成与后续范围

修改模型、刀具、基准、测量或参数后增加任务修订号，作废受影响的旧刀路、仿真与NC证据。用同修订的证据执行 `check_job.py --stage delivery --capabilities ... --evidence ...`。

交付时明确区分：计划已确认、刀路已计算并保存、仿真已验证、NC已导出、现场已试切。不能由软件成功推断实际长度/精度已经合格，也不能保证不发生断刀。

最终交付的工作工程文件优先使用简洁中文名，例如`支架加工.mks`、`薄板加工.mks`；用户指定名称时沿用其名称。测试稿可用`支架试算.mks`，确需区分版本时只加简短编号，如`支架加工2.mks`。日期、材料参数、MCP/TEST/VERIFIED等调试标签和完整验证说明放入任务记录，不堆叠在最终工程文件名中。优先在建立隔离副本时确定名称；已有工程不为改名而覆盖原文件，改名/交付副本后须更新路径绑定并核对可重新打开。

`cam_test` 只验收明确的测试范围，并持续标记不是完整零件。`production_cam` 不得用浅层测试或缺少必需工序的结果宣告全部目标完成。

现场探测、移动、换刀、回零和切削属于另外的执行范围。当前服务不提供运动工具；不得借MDI、外部G-code发送、Computer Use等绕过。若未来有受支持的设备层，仍须按现场基准、装夹、仿真/空气运行和实际授权判断，不从本技能的存在推定许可。

本技能默认可以自动匹配相关请求，也可显式使用 `$makera-studio-cam`。不将历史任务的牌号、测点、刀具、进给或工序深度作为其他任务默认值。
